# Proposed changes from X3 (ENV-B, `ext/optico`) to X1's shared layer and the agent seam

Each item is outside X3's area; ENV-B works today with the workaround named, so none blocks the ENV-B arms.

| # | Where (owner X1) | Observation | Proposed change | ENV-B workaround now |
|---|---|---|---|---|
| 1 | `agent/optimize.py` (hooks seam) | `view = hooks.task_view()` is computed once, before the start screen, and every turn re-renders that same dict. Design §3.4 wants the B-IS proposer to see OptiCo's performance table (all trials so far) in OptiCo's own format, so ENV-B's view changes every turn. | Re-call `hooks.task_view()` in `render()` when hooks are present (one line), or add `hooks.refresh_view()`. | `OptiCoHooks.task_view()` returns `_Live` entries for `performance_table`, `current_best`, `trials_so_far`; `render()` serializes the view with `json.dumps(..., default=str)` every turn, which re-evaluates them (CPU-tested in `test_optico_task_baselines.py`). This relies on `default=str` staying in `render()` and in `_jsonable`. |
| 2 | `ext/common/env_runner.py::EnvRunner.receipt` | `judge_valid = result.judge_valid and finite metric` rewrites the environment judge's own verdict when the adapter returns no metric, while the guard rejections stay in the receipt; the receipt then says "judge failed" and counts guard rejections at the same time (judge/guard separation, design §8 risk 14; Codex finding on X3's review). | Keep `judge_valid = result.judge_valid`; add "no metric" as its own invalid reason (or as a generic `output_integrity` guard) without touching the judge verdict. | `trial.evaluate` always returns a judge-consistent metric for judge-success rows (exact iterations 3-5, else the mean over the lines OptiCo averaged), so the rewrite never triggers for ENV-B. |
| 3 | `ext/common/node_ext.listdir` | Raises `NotADirectoryError` for a path that is a file (only `FileNotFoundError` is caught). | Return `None` for anything that is not a directory. | `native._collect` skips names with a dot and catches the error per entry. |
| 4 | `ext/common/node_ext.kill_token` + launch scripts | A bash script that does `export INFRARSI_TOKEN=...` after it started does not carry the token in `/proc/<pid>/environ`, so `kill_token` kills its children but not the script itself. | Document it, or launch with `launch(script, log, env={'INFRARSI_TOKEN': token})` so the top-level script carries the token from exec. | Harmless for ENV-B: `trial.sh`/`loop.sh` only wait on their children and then write status/hash files; the B-NAT driver checks the node's stop stamp before `status.json`. |
| 5 | `agent/search.py::SearchSession._admission`, `ext/common/env_runner.py::EnvRunner.run` (H-05) | ENV-B now implements the HarnessScreenRunner admission protocol as `_admission` calls it today: `bounded_cap(gpu_hours_left, world, wall_left, expected_s) -> int or None` (the admitted node wall W), `worst_case_gpu_hours(world, wall_cap)` (`wall_cap <= 0` → 0, the empty pair reserve), `pair_wall_cap(expected_s) -> 0`, `stop_grace_s = 0`, plus `worst_case_wall_s(wall_cap)` and `attempt_overhead_s(bounded)`. The runner's worst case already contains its whole attempt overhead. `EnvRunner.run` drops `wall_cap`. `_expected_wall()` falls back to 900 s before the first screen. | If `_admission` changes, keep these names and meanings, or tell X3 the new ones. Passing `wall_cap` through `EnvRunner.run` to `execute()` would let every ext runner use it. A runner-supplied prior (e.g. `runner.expected_wall_s()`) would replace the 900 s fallback. | `OptiCoRunner.run` pops `wall_cap` before calling the base and uses it in `execute()` (`DEADLINE_S` on the node); `bounded_cap` floors the expected wall at the workload's default trial + 30 s. |
| 6 | `ext/common/env_runner.py::EnvRunner.run` (Codex follow-up-2 review, round 2) | `held` is taken before `lease.release()`, so the release RPCs (and their retries) are never charged in `cost.gpu_seconds`; `cost.accounting_complete` stays true when `lease.acquired` is still non-empty (a kept lease keeps costing). | Take `held` after `release()` returns; set `cost.accounting_complete = False` (and a reason) whenever claims remain held. | ENV-B bounded attempts record the whole attempt wall (`receipt.deadline.actual_s`, lease-to-release); a kept lease is visible in `lease_release.kept` and `containment`. |
| 7 | `ext/common/trajectory.py` (`events`, `arm_row`, `compare`) | `cum.accounting_complete` / `used.accounting_complete` of a trace are ignored: an incomplete trace (B-NAT row without a node stamp, unmeasured clock offset, ambiguous call attribution, kept lease; also SearchSession traces with unknown LLM cost) yields exact-looking CTG / AUC and can feed a label. | `arm_row` reports `accounting_complete` (all screens' `cum` and `used`); `compare` labels a pair `incomplete` (or reports bounds) when either side is incomplete. | B-NAT traces set the flags and list the reasons in `extra.accounting_notes`; until 7 lands the analysis must check them by hand. |
| 8 | `ext/common/remote_exec.py::GpuLease.acquire` | A path is appended to `acquired` only after `ops.acquire()` returns; if the claim is created on the node but the answer is lost, rollback does not know it and the claim stays (owned by this attempt, invisible to `release_failures`). | Mark the path pending before the RPC and, on any exception, `release_status(path, attempt_id)` it too (owner-checked, so a foreign lease is never touched). | ENV-B bounded attempts: `DeadlineOps` does exactly this for a failed `acquire` (`receipt.deadline.ambiguous_acquires`). Unbounded attempts and the B-NAT driver rely on the 300 s default timeout. |
| 9 | `agent/search.py::SearchSession.screen` (same-failure stop) — **applied by X3 with O's approval, 2026-10-21** | Only `occupied_sibling` was exempt from the same-failure×6 counter, so an ENV-B attempt refused before anything was launched (pre-launch deadline or transport trouble in lease/upload, now reason `infra_refusal`) counted as a failure of the candidate (`bis_w3_a` lost c0 and c1 that way). | One line: `sibling = reason in ('occupied_sibling', 'infra_refusal')` (comment updated); `occupied` still counts. | ENV-B tests: 8 refusals in a row end on `budget:screens`, not `same_failure_x6`; tests/cpu/agent and the co-location test pass (449). |
